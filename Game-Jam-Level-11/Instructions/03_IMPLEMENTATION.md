# 03. План реализации в Unity

Документ рассчитан на текущую заготовку проекта: Unity 6000.0.83f1, 2D URP, Input System и uGUI. На момент написания игровые скрипты и префабы ещё не подготовлены.

## Предлагаемая структура Assets

Создавать эту структуру вручную в Unity Editor. Все префабы — отдельные файлы, а не объекты, собираемые кодом.

- Assets/Art/Sprites
- Assets/Art/Materials
- Assets/Audio/Music
- Assets/Audio/SFX
- Assets/Prefabs/Player/PF_Player.prefab
- Assets/Prefabs/Gameplay/PF_FuelPickup.prefab
- Assets/Prefabs/Gameplay/PF_Cover.prefab
- Assets/Prefabs/UI/UI_HUD.prefab
- Assets/Prefabs/UI/UI_StartPanel.prefab
- Assets/Prefabs/UI/UI_ResultPanel.prefab
- Assets/Scenes/Main.unity
- Assets/Scripts/Core
- Assets/Scripts/Player
- Assets/Scripts/Gameplay
- Assets/Scripts/UI
- Assets/Settings
- Assets/InputSystem_Actions.inputactions

Не обязательно создавать все пустые папки сразу. Создавать только те, которые используются.

## Префабы и обязанности

### PF_Player

Содержит:

- SpriteRenderer;
- Rigidbody2D и Collider2D;
- компонент управления движением;
- визуальный дочерний объект защиты, заранее созданный в префабе и выключенный по умолчанию;
- Light2D или ссылку на заранее созданный источник света.

Настраиваемые поля:

- обычная скорость;
- множитель скорости при защите;
- ссылка на визуал защиты;
- ссылка на источник света;
- максимальный запас огня;
- скорость обычного расхода;
- ссылка на UI-представление, если оно обновляется напрямую.

### PF_FuelPickup

Содержит SpriteRenderer, Collider2D с Is Trigger и компонент точки топлива.

Настраиваемые поля:

- количество восстанавливаемого огня;
- задержка до повторного появления;
- визуал активного/неактивного состояния.

Разместить четыре экземпляра на уровне вручную. При сборе выключать экземпляр и по завершении cooldown включать этот же экземпляр. Новые объекты не создавать.

### PF_Cover

Статический объект с визуалом и Collider2D. Укрытия расставляются вручную и не двигаются в MVP. Их задача — дать игроку безопасные маршруты во время ветра.

### UI_HUD

Заранее собранный префаб интерфейса:

- Slider или Image Filled для запаса огня;
- текст времени;
- индикатор надвигающегося ветра;
- необязательный счётчик топлива.

У всех элементов заранее выставлены anchors, размеры, шрифты и цвета. В рантайме меняются только значения существующих компонентов.

### UI_StartPanel и UI_ResultPanel

Самостоятельные префабы. Кнопки и обработчики заранее размещены и связаны в Inspector. Панель результата переключает текст победы/поражения и отображает итоговое время через уже существующие Text-компоненты.

## Скриптовые роли

Не создавать монолитный скрипт, который одновременно управляет игроком, интерфейсом, ветром и топливом. Достаточно нескольких простых компонентов:

- **GameManager** — состояние игры (Start / Playing / Won / Lost), запуск, завершение, таймер матча и перезапуск.
- **PlayerController** — движение и удержание защиты.
- **FlameMeter** — запас огня, обычное уменьшение, пополнение от топлива и событие изменения значения.
- **WindController** — предупреждение, направление/сила порыва и активное время ветра.
- **FuelPickup** — триггер сбора и cooldown конкретного заранее размещённого экземпляра.
- **HUDView** — обновление существующих Slider/Image/Text и показ заранее созданных панелей.

Скрипты должны получать ссылки через serialized fields. Не использовать глобальный поиск объектов для нормального потока игры.

## Связь систем

1. GameManager переводит игру в Playing после нажатия Start на заранее размещённой кнопке.
2. PlayerController читает Move и Protect из Input System.
3. FlameMeter уменьшает запас огня по времени и принимает пополнение от FuelPickup.
4. WindController сообщает, когда начинается предупреждение и когда активен порыв. PlayerController проверяет защиту; укрытия должны давать безопасную зону через заранее настроенные Collider2D/Trigger.
5. FlameMeter передаёт новое значение HUDView. HUDView обновляет заполнение полосы и вызывает обновление Light2D через заранее назначенную ссылку.
6. При нуле огня GameManager завершает игру как Lost. При достижении 180 секунд — Won. UI_ResultPanel уже существует в сцене и только включается.

Для события изменения запаса огня можно использовать C# event/action или прямую сериализованную ссылку — выбрать простейший вариант, который понятен команде.

## Input System

Использовать существующий Input System package и Input Actions asset. Минимальные действия:

- Move — Vector2, WASD/стрелки;
- Protect — Button, удержание Space;
- Start/Retry — кнопки UI.

Если в текущем Input Actions нет Protect, добавить это действие в редакторе и назначить binding. Не создавать Input Actions Asset в рантайме.

## Первая тестовая сборка

Перед визуальной полировкой проверить только:

- движение игрока;
- удержание защиты и замедление;
- четыре точки топлива;
- расход и пополнение огня;
- предупреждение и порыв ветра;
- победу/поражение;
- Retry без создания новых объектов.

После этого настраивать ощущение скорости, длину порыва, расход огня и радиус света. Только затем добавлять звук, экранные эффекты и дополнительные детали.
