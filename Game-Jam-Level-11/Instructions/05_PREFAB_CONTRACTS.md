# 05. Контракты префабов

Документ фиксирует, какие отдельные префабы должны быть доступны для настройки. Это особенно важно для интерфейса: внешний вид и расположение UI нельзя зашивать в код.

## Общее правило

Каждый перечисленный элемент создаётся в Unity Editor как Prefab Asset. Экземпляры размещаются в сцене заранее. Скрипты получают ссылки через Inspector и во время игры только изменяют состояние существующих экземпляров.

Если хочется изменить размер панели, шрифт, цвет, отступ, анимацию, иконку, звук, скорость или количество — это должно делаться в Prefab Mode / Inspector без изменения игрового кода.

## Игровые префабы

| Префаб | Содержимое | Что настраивается в Inspector |
|---|---|---|
| Player.prefab | SpriteRenderer, Rigidbody2D, Collider2D, PlayerController, Light2D, визуал защиты | Скорость, скорость под защитой, ссылки на свет и визуал защиты, параметры движения и огня |
| PickupRoot.prefab | SpriteRenderer, Trigger Collider2D, FuelPickup | Восстановление огня, cooldown, визуал, звук сбора |
| EnvironmentRoot.prefab / Cover.prefab | Визуал укрытия, Collider2D, CoverZone | Размер, форма зоны, визуал, событие входа/выхода |

На уровне заранее разместить четыре экземпляра топлива и несколько укрытий. Позиции и количество менять в Editor, не через генератор.

## UI-префабы

| Префаб | Содержимое | Что настраивается в Inspector |
|---|---|---|
| UI_HUD.prefab | Корневой Canvas, CanvasScaler, GraphicRaycaster | Reference Resolution, режим масштабирования, сортировка |
| UI_FlameMeter.prefab | Иконка огня, фон и заполнение полосы, необязательная подпись | Спрайты, цвета, размеры, anchors, анимация заполнения |
| UI_Timer.prefab | Текст оставшегося времени | Шрифт, размер, формат времени, позиция |
| UI_WindWarning.prefab | Иконка/текст предупреждения о ветре | Иконка, текст, цвет, анимация, позиция |
| UI_StartPanel.prefab | Название игры, цель, подсказки управления, кнопка Start | Все тексты, шрифты, цвета, фон, размеры, кнопка |
| UI_ResultPanel.prefab | Результат Won/Lost, итоговое время, кнопка Retry | Тексты, оформление победы/поражения, шрифты, кнопка |
| UI_PausePanel.prefab | Пауза и кнопка продолжения (необязательно) | Тексты, оформление и кнопки |

Вложенные UI-префабы вручную разместить внутри UI_HUD (Canvas) или внутри заранее подготовленных панелей. Не вызывать Instantiate при открытии панели и не добавлять элементы в Canvas скриптом.

## Контракты ссылок

Назначить следующие ссылки через Inspector:

- GameManager → PlayerController, FlameMeter, WindController, UI_StartPanel, UI_ResultPanel, HUDView.
- PlayerController → Rigidbody2D, визуал защиты, Light2D или объект, который управляет радиусом света.
- FlameMeter → заранее существующий визуальный источник света (или событие изменения значения).
- FuelPickup → FlameMeter или заранее настроенный получатель топлива.
- CoverZone → UnityEvent<bool> вызывает PlayerController.SetInCover(bool).
- HUDView → существующие Image / Slider / Text и UI-панели.

Не искать эти объекты в рантайме через FindObjectOfType, FindFirstObjectByType или GameObject.Find.

## Состояния UI

Все экраны существуют до нажатия Play:

- Старт: UI_StartPanel включён, игровой HUD может быть видим, управление и ветер ещё не активны.
- Игра: UI_StartPanel выключен, HUD включён, UI_ResultPanel выключен.
- Победа или поражение: UI_ResultPanel включён, управление и ветер остановлены.
- Retry: сбросить значения, вернуть заранее размещённые объекты в начальное состояние и снова включить UI_StartPanel.

Переключение уже существующих объектов через SetActive допустимо. Создавать новый Canvas, панель или дочерние элементы запрещено.

## Проверка готовности каждого префаба

- [ ] Префаб можно открыть и полностью оформить в Prefab Mode.
- [ ] Все визуальные параметры доступны без правки C#.
- [ ] Все нужные ссылки назначаются через Inspector.
- [ ] В префабе нет зависимости от глобального поиска объектов.
- [ ] Префаб размещён в сцене до запуска игры.
- [ ] Скрипт не создаёт и не перестраивает его иерархию в рантайме.
- [ ] Для UI заранее созданы все тексты, изображения, кнопки и индикаторы.
